# The Rosinfotech Base Standards

## The Git Flow Standard

### Variants

#### Rule #2610082124

* Context:

  * Solo work or a circle of fully trusted peers, many tasks - isolation per task becomes valuable for context switching and parallel experiments;

* Description:

  * A task branch forks from main and merges back into main;

  * The merges are free - trust replaces the gate, there are no merge requests;

  * Parallel tasks run in git worktrees - one worktree per task in flight;

  * main deploys to production;

  * The deviation from the canon: the original GitHub Flow presumes a pull request with review - for a trusted circle the request degenerates into a free merge;

* Scheme:

  ```mermaid
  flowchart LR
      T["branch-task<br>(fork: main)"] -->|"merge"| M["main"]
      M --> PE[("prod")]
  ```

* Benefits:

  * Per-task isolation without per-task ceremony;

  * Worktrees keep parallel contexts independent - no stashes, no re-checkouts;

  * A broken task branch is dropped without a trace in main;

* Examples:

  * Case #1:

    * Incorrect:

      * three tasks interleaved in one working copy, the stash list as a task tracker;

    * Correct:

      * three worktrees, three task branches, each merged into main on completion.
