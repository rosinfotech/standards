# The Rosinfotech Base Standards

## The Documentation Standard

### Formation

#### Rule #2609271055

* Context:

  * The standards catalog grows; without a fixed formation scheme the structure drifts - folders stop mirroring the index and rules scatter;

* Description:

  * Any standard is formed as a set of rules: one rule carries one norm;

  * Each standard corresponds to a second-level section (`##`) of the index (README.md);

  * Each standard has its own folder under `standards/` named after its section in kebab-case with the `-standard` suffix;

  * Rule files lie flat in the standard's folder;

  * Non-rule artifacts of the standard live in the standard's `assets/` subfolder:

    * the rule scheme (`scheme.md`);

    * agent files (`AGENTS-STANDARD-*.md`);

  * Assets are pure ready-to-copy files - isolated and independent:

    * they carry no references to rules - links and `Rule #<UTLBL>` mentions are a violation;

    * the norms are inlined as plain text;

    * their description lives in the rules;

  * The pointer asset exception: a file whose purpose is to declare and reference - not to carry norms (the flow markers of the Git Flow Standard) - carries the declaration and the URLs of the standard and its rules; it inlines no norms;

  * The standard's index section links every rule of the standard;

  * The folder structure mirrors the index structure at the second level;

* Benefits:

  * Predictable navigation: the index and the folders map 1:1;

  * Uniform growth: a new standard follows the same steps every time;

  * Findability: every norm is reachable by its rule identifier;

* Examples:

  * Case #1 - formation of a new standard:

    * add a `## The X Standard` section to the index (README.md);

    * create the `standards/x-standard/` folder;

    * add rule files per [Rule #2609271057](/standards/documentation-standard/rule-2609271057.md) and link them from the index section;
