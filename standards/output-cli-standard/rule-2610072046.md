# The Rosinfotech Base Standards

## The Output CLI Standard

### Typography

#### Rule #2610072046

* Context:

  * A line longer than the terminal wraps chaotically; unbroken paths force horizontal scrolling in CI logs;

* Description:

  * The working line limit is 100 characters - the parallel of [Rule #2610031264](/standards/common-code-style-standard/rule-2610031264.md);

  * When the terminal width is known and smaller, the limit is min(100, terminal width);

  * The wrap uses a hanging indent of 4 spaces - the continuation line starts +4 relative to the first line;

  * Paths and URLs are never broken across lines: an overlong one truncates in the middle with `…`;

  * The full untruncated form is available in verbose or machine mode;

* Benefits:

  * No chaotic terminal wrapping, no horizontal scroll in CI;

  * Copy-pasting a path from the output stays possible;

* Examples:

  * Case #1 - a long message:

    * Incorrect (127 characters, wraps at the terminal's mercy):

      ```text
      Warning: the migration 2610071900 "rename user activation timestamp column" was skipped because its precondition failed
      ```

    * Correct (hanging indent +4):

      ```text
      Warning: the migration 2610071900 "rename user activation timestamp column" was
          skipped because its precondition failed
      ```

  * Case #2 - an overlong path:

    ```text
    Error: cannot read src/features/deployment/…/config.production.yaml
    Hint: run with --verbose for the full path
    ```
