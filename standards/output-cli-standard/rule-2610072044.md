# The Rosinfotech Base Standards

## The Output CLI Standard

### Typography

#### Rule #2610072044

* Context:

  * Without one enumeration of the blocks every rule re-describes them its own way; without one separator discipline the logical parts merge into a wall of text;

* Description:

  * The block types of the CLI output:

    * Heading - a plain colored line, no markers, no bold; the shades are declared per role in [Rule #2610072036](/standards/output-cli-standard/rule-2610072036.md):

      * Two levels exist - the position in the hierarchy assigns the level, not the visual weight of the section;

      * Level 1 marks the global sections - the top-level parts the output of the command divides into;

      * Level 2 marks the subsections of a global section - a level-2 heading always belongs to one level-1 section;

      * The hierarchy starts at level 1: a level-2 heading without a level-1 parent in the same output is a violation - the output never opens at level 2;

      * The hierarchy belongs to one command output: every command builds its own levels - they are not inherited from a parent command, a wrapper or a previous run;

      * One heading form per level within the output of one command: every level-1 heading carries the Heading 1 shade, every level-2 heading carries the Heading 2 shade (per [Rule #2610072036](/standards/output-cli-standard/rule-2610072036.md)) - one level rendered in two forms within one output is a violation;

      * Marker decorations, ALL CAPS walls, figlet banners, `====` / `----` underline runs, box-drawing frames are violations;

    * Special message and hint - the `TYPE. Text` format in the semantic color (per [Rule #2610072048](/standards/output-cli-standard/rule-2610072048.md));

    * Paragraph - the main text: the sentences flow inline, each opens with a capital letter, periods separate them, the trailing period stays;

    * Prompt - the interactive question block (per [Rule #2610072056](/standards/output-cli-standard/rule-2610072056.md));

    * List - the nested dash or numbered structure (per [Rule #2610072042](/standards/output-cli-standard/rule-2610072042.md)) - the complex block with its own rule;

    * Table - the columnar data block:

      * The header row;

      * The separator row of dashes under the header - each column's dashes span the widest cell of that column;

      * Dense data rows;

  * The common output rules - every block, no exceptions:

    * Exactly one blank separator line follows every block - including the last block of the output;

    * No block receives a separator blank line above itself; the list-internal separations are defined by [Rule #2610072042](/standards/output-cli-standard/rule-2610072042.md) and are not block separators;

    * Two or more blank lines in a row are a violation - the CLI guarantees their absence across its own output;

  * The frame: every run opens with one blank line before its first output and closes with the trailing separator after the last block - the redirected file tells the same story as the terminal, only without the color (per [Rule #2610072030](/standards/output-cli-standard/rule-2610072030.md)); the explicit machine modes (`--tsv`, `--json`) stay plain - no frame there (per [Rule #2610072052](/standards/output-cli-standard/rule-2610072052.md));

  * The relay exception: an external utility's output (`df`, `systemctl`, `docker` ...) is passed through as-is - the inner spacing belongs to the utility and is not reformatted; the relayed block is framed by one blank line before and after;

* Benefits:

  * One enumeration: the blocks and their common discipline live in one place, the complex blocks branch into their own rules;

  * Every logical part is visually delimited; nothing merges into a wall of text;

  * The redirected copy is a faithful mirror of the terminal run;

* Examples:

  * Case #1 - the block sequence (the roles noted on the right; the shades live in [Rule #2610072036](/standards/output-cli-standard/rule-2610072036.md)):

    ```text
    Deploy report                     <- Heading 1

    Region EU                         <- Heading 2

    The deploy applied 4 migrations. Two tests were skipped, not failed.

    Warning. 2 flaky tests skipped    <- Special message

    - Item 1;
    - Item 2;
    ```

  * Case #2 - a message glued to its list:

    * Incorrect (the warning runs into the positions):

      ```text
      Warning. Pending updates: 2 (security: 1):
      docker-buildx-plugin/resolute 0.38.0-1~ubuntu.26.04 amd64
      ```

    * Correct (one blank line after the message, the list positions follow):

      ```text
      Warning. Pending updates: 2 (security: 1):

          - docker-buildx-plugin/resolute 0.38.0-1~ubuntu.26.04 amd64;
      ```

  * Case #3 - doubled blank lines:

    * Incorrect:

      ```text
      Checks


      - Db: ok;
      ```

    * Correct:

      ```text
      Checks

      - db: ok;
      ```

  * Case #4 - the heading hierarchy:

    * Incorrect (the output opens at level 2 - no global section exists):

      ```text
      Region EU

      The deploy applied 4 migrations. Two tests were skipped, not failed.
      ```

    * Correct (level 1 opens the global section, level 2 subdivides it):

      ```text
      Deploy report

      Region EU

      The deploy applied 4 migrations. Two tests were skipped, not failed.
      ```
