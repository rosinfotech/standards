# The Rosinfotech Base Standards

## The Output CLI Standard

### Typography

#### Rule #2610072044

* Context:

  * Random vertical spacing hides block boundaries; without a blank line after every paragraph and message the logical parts merge into a wall of text - hard to scan in a terminal and in a log;

* Description:

  * Exactly one blank line follows every header (per [Rule #2610072040](/standards/output-cli-standard/rule-2610072040.md));

  * Exactly one blank line follows every paragraph - a paragraph is one or more consecutive text lines forming a single logical part;

  * Exactly one blank line follows every message line or block - `Error:` / `Warning:` / `Success:` / `Information:` per [Rule #2610072048](/standards/output-cli-standard/rule-2610072048.md) - before any following content;

  * Exactly one blank line before and after every (sub)list block and every table block;

  * Two or more blank lines in a row are a violation - the CLI guarantees their absence across its own output;

  * The relay exception: a retransmission of an external utility's output (`df`, `systemctl`, `docker` ...) is passed through as-is - the inner spacing belongs to the utility and is not reformatted;

  * The relayed block is framed: exactly one blank line before it and after it separates the verbatim content from the surrounding output;

  * The frame: in TTY mode the output is preceded and followed by one blank line - the first and the last line of the output;

  * In non-TTY mode (log, pipe, CI) the frame lines are absent;

  * The output ends with its last text line plus a single `\n` - no trailing blank lines beyond the frame;

* Benefits:

  * Every logical part - paragraph, message, list, table, relay - is visually delimited; nothing merges into a wall of text;

  * Interactive output breathes: the frame separates it from the prompt and the previous command;

  * Log files stay dense: concatenated entries carry no wasted blank lines;

* Examples:

  * Case #1 - a message glued to its list:

    * Incorrect (the warning runs into the package list):

      ```text
      Warning: pending updates: 2 (security: 1):
      docker-buildx-plugin/resolute 0.38.0-1~ubuntu.26.04 amd64
      libpng16-16t64/resolute 1.6.57-1ubuntu0.1 amd64
      ```

    * Correct (one blank line after the message, the list positions follow):

      ```text
      Warning: pending updates: 2 (security: 1):

          - docker-buildx-plugin/resolute 0.38.0-1~ubuntu.26.04 amd64;
          - libpng16-16t64/resolute 1.6.57-1ubuntu0.1 amd64;
      ```

  * Case #2 - a relayed utility output:

    ```text
    == Disk usage (df -h) ==

    Filesystem      Size  Used Avail Use% Mounted on
    tmpfs           1.6G  1.2M  1.6G   1% /run
    /dev/vda2       118G   11G  102G  10% /

    Success: report generated in 3.1s
    ```

  * Case #3 - doubled blank lines:

    * Incorrect:

      ```text
      -- Checks --


      - db: ok;
      ```

    * Correct:

      ```text
      -- Checks --

      - db: ok;
      ```
