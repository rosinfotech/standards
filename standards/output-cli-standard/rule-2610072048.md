# The Rosinfotech Base Standards

## The Output CLI Standard

### Messages

#### Rule #2610072048

* Context:

  * Without a uniform message anatomy, automation cannot match errors and humans cannot scan a log;

* Description:

  * The prefix set is closed: `Error:`, `Warning:`, `Success:`, `Information:`;

  * The message is colored fully (per [Rule #2610072036](/standards/output-cli-standard/rule-2610072036.md)): the prefix is bold with the semantic color, the text carries the semantic color without bold;

  * A single-sentence message stays on the prefix line;

  * A multi-sentence message occupies its own block:

    * the prefix alone on its line;

    * one blank line;

    * the message text indented +4 spaces, one or more lines;

    * one blank line after the block;

  * A one-line message has no trailing period; a multi-sentence message keeps periods inside;

  * Every message line or block is followed by one blank line before any next content (per [Rule #2610072044](/standards/output-cli-standard/rule-2610072044.md));

  * Secondary hints follow the block as gray `Hint:` lines (per [Rule #2610072036](/standards/output-cli-standard/rule-2610072036.md));

  * Messages are in English; machine-stable error labels follow the UTLBL of [Rule #2103051010](/standards/common-code-style-standard/rule-2103051010.md);

  * Emoji and symbol markers instead of the prefix are a violation;

* Benefits:

  * `grep '^Error:'` finds every failure across every CLI;

  * The four prefixes cover the full verdict space - no per-tool vocabularies;

* Examples:

  * Case #1 - single-sentence messages:

    ```text
    Error: unknown flag "--regoin"
    Warning: 2 flaky tests skipped
    Success: deployed in 8.2s
    Information: next maintenance window on Sunday 02:00
    ```

  * Case #2 - a multi-sentence message with a hint:

    ```text
    Error:

        server-b: failed to connect. The timeout of 5s expired before the handshake.

    Hint: check the VPN tunnel before retrying
    ```

  * Case #3 - shouting:

    * Incorrect:

      ```text
      ERROR!!! port 8080 already in use :(
      ```

    * Correct:

      ```text
      Error: port 8080 already in use
      ```
