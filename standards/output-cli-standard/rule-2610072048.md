# The Rosinfotech Base Standards

## The Output CLI Standard

### Messages

#### Rule #2610072048

* Context:

  * Without a uniform message anatomy, automation cannot match errors and humans cannot scan a log;

* Description:

  * The prefix set is closed: `Error`, `Warning`, `Success`;

  * The format is `TYPE. Text` - the prefix, a period, a space, the text;

  * Information is the prefixless message: the text alone in the Information color (per [Rule #2610072036](/standards/output-cli-standard/rule-2610072036.md)) - a leading `Information.` is a violation;

  * The whole line carries the semantic color (per [Rule #2610072036](/standards/output-cli-standard/rule-2610072036.md)) - no bold anywhere;

  * The text opens with a capital letter;

  * A multi-sentence message flows inline: the sentences separate with periods, the trailing period is dropped;

  * Hints: `Hint. Text` lines in the hint color follow their message (per [Rule #2610072036](/standards/output-cli-standard/rule-2610072036.md)); hint sentences flow inline and keep the trailing period;

  * Messages are in English; machine-stable error labels follow the UTLBL of [Rule #2103051010](/standards/common-code-style-standard/rule-2103051010.md);

  * Emoji and symbol markers instead of the prefix are a violation;

* Benefits:

  * `grep '^Error\.'` finds every failure across every CLI;

  * The three prefixes cover the verdict space - no per-tool vocabularies; the informational note reads as a calm colored line, not as a shouting prefix;

* Examples:

  * Case #1 - single-sentence messages:

    ```text
    Next maintenance window on Sunday 02:00    <- Information, no prefix

    Success. Deployed in 8.2s

    Warning. 2 flaky tests skipped

    Error. Port 8080 already in use
    ```

  * Case #2 - a multi-sentence message and a hint:

    ```text
    The window opens at 02:00. The downtime stays under 5 minutes    <- Information

    Hint. Check the VPN tunnel before retrying.
    ```

  * Case #3 - shouting and the colon legacy:

    * Incorrect:

      ```text
      ERROR!!! port 8080 already in use :(
      ```

    * Incorrect (the colon separator is abolished):

      ```text
      Error: port 8080 already in use
      ```

    * Correct:

      ```text
      Error. Port 8080 already in use
      ```
