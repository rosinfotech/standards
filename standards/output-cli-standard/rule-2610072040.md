# The Rosinfotech Base Standards

## The Output CLI Standard

### Typography

#### Rule #2610072040

* Context:

  * Banners and capital-letter walls eat terminal space and carry no information; the hierarchy must survive plain text without color;

* Description:

  * Four heading levels - the marker carries the level:

    * `== H ==` - level 1: bold + blue;

    * `-- H --` - level 2: bold + blue;

    * `-- H --` - level 3: blue without bold;

    * flat text - level 4: bold + white;

  * The level is chosen by the weight of the section - starting from level 1 is not required;

  * Headers stand at column 0; after a header of any level the content restarts at indent 0;

  * Exactly one blank line follows every header (per [Rule #2610072044](/standards/output-cli-standard/rule-2610072044.md));

  * Color and bold reset in log/NO_COLOR mode (per [Rule #2610072034](/standards/output-cli-standard/rule-2610072034.md)) - the markers `==` / `--` survive as plain text and carry the hierarchy;

  * Violations: ALL CAPS walls, figlet banners, `====` / `----` underline runs, box-drawing frames;

* Benefits:

  * The hierarchy is readable with and without color - in a terminal and in a CI log;

  * The output stays compact in small terminals;

* Examples:

  * Case #1 - four levels in one report (the colors noted on the right):

    ```text
    == Deploy report ==      <- bold + blue

    -- Changes --            <- bold + blue

    -- Region EU --          <- blue without bold

    Checks                   <- bold + white

    - server-a:
    ```

  * Case #2 - level 2 without a preceding level 1 (the section weight decides):

    ```text
    -- Source files --

    - src/cli.ts;
    - src/main.ts;
    ```

  * Case #3 - banner violations:

    * Incorrect:

      ```text
      ========================================
          DEPLOY REPORT - PRODUCTION
      ========================================
      ```

    * Correct:

      ```text
      == Deploy report ==
      ```
