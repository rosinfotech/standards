# The Rosinfotech Base Standards

## The Output CLI Standard

### Streams

#### Rule #2610072030

* Context:

  * A redirected copy that loses the warnings hides half of what happened - the file must tell the same story as the terminal;

* Description:

  * Everything the CLI prints - the result, special messages, hints, prompt refusals - goes to stdout;

  * The redirected file contains everything the terminal showed, only without the color (per [Rule #2610072034](/standards/output-cli-standard/rule-2610072034.md));

  * The single transient exception is the progress line (per [Rule #2610072054](/standards/output-cli-standard/rule-2610072054.md)): it is redrawn and erased, suppressed entirely in a non-TTY stream - it never reaches a file;

  * The machine verdict travels in the exit code (per [Rule #2610072032](/standards/output-cli-standard/rule-2610072032.md)) - `mycli deploy && announce` works on codes, not on parsing;

  * Default loggers of the stack's libraries are captured into the CLI's own output - never left to write around it;

* Benefits:

  * The file copy is complete: warnings and hints survive every redirect and every tee;

  * One stream - no interleaving puzzles between stdout and stderr in pipes and CI;

* Examples:

  * Case #1 - a warning lost by the stderr legacy:

    * Incorrect (the warning stayed in the terminal - the file lost it):

      ```text
      $ mycli list > out.txt
      Warning. 2 items skipped

      $ cat out.txt
      src/cli.ts
      src/main.ts
      ```

    * Correct (the file tells the same story, minus the color):

      ```text
      $ mycli list > out.txt
      $ cat out.txt

      Warning. 2 items skipped

      src/cli.ts
      src/main.ts

      ```
