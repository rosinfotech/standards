# The Rosinfotech Base Standards

## The Output CLI Standard

### Streams

#### Rule #2610072030

* Context:

  * Mixed output breaks pipelines: a warning printed to stdout ends up inside `cli > file` and corrupts the result for every consumer;

* Description:

  * The command result (data, answer, listing) goes to stdout only;

  * Diagnostics - progress, logs, warnings, errors - go to stderr;

  * The check: `cli > out.txt` leaves a clean result in the file while diagnostics stay visible in the terminal;

  * Default loggers of the stack's libraries are re-routed to stderr, never left on stdout;

* Benefits:

  * Composable pipelines: `cli | grep` and `cli > report.tsv` always work;

  * The result is reproducible and diffable;

* Examples:

  * Case #1 - a warning polluting the result:

    * Incorrect:

      ```text
      $ mycli list > out.txt
      $ cat out.txt
      Warning: 2 items skipped
      src/cli.ts
      src/main.ts
      ```

    * Correct (the warning went to stderr and stayed in the terminal):

      ```text
      $ mycli list > out.txt
      Warning: 2 items skipped
      $ cat out.txt
      src/cli.ts
      src/main.ts
      ```

  * Case #2 - a command whose result IS a diagnostics report:

    * `mycli doctor` prints its report to stdout (the report is the result), while its own progress spinner goes to stderr;
