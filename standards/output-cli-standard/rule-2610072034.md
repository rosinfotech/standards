# The Rosinfotech Base Standards

## The Output CLI Standard

### Color

#### Rule #2610072034

* Context:

  * ANSI escapes written into a pipe or a file corrupt the data for every downstream tool - editors, grep, diff, JSON parsers;

* Description:

  * Color is emitted only when the target stream is a TTY;

  * The environment switches are checked in order - the first match wins:

    * `CLICOLOR_FORCE` (any value except 0) - color on, even into a pipe;

    * `NO_COLOR` (any non-empty value, the reference: https://no-color.org) - color off;

    * `CLICOLOR=0` - color off;

    * `TERM=dumb` - color off;

    * otherwise the stream's TTY state decides;

  * The flags `--no-color` / `--color` override the environment variables;

  * ANSI escapes in a redirected stream without `CLICOLOR_FORCE` are a violation;

* Benefits:

  * `cli > file` produces clean data without a "no-color" flag;

  * Standard environment switches work without custom documentation;

  * The switch precedence is deterministic and testable;

* Examples:

  * Case #1 - escapes leaking into a file:

    * Incorrect:

      ```text
      $ mycli list > out.txt
      $ cat -v out.txt
      ^[[36msrc/cli.ts^[[0m
      ```

    * Correct:

      ```text
      $ mycli list > out.txt
      $ cat -v out.txt
      src/cli.ts
      ```

  * Case #2 - forcing color for a TTY-like consumer:

    ```text
    $ CLICOLOR_FORCE=1 mycli list | less -R
    ```
