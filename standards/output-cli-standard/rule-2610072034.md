# The Rosinfotech Base Standards

## The Output CLI Standard

### Color

#### Rule #2610072034

* Context:

  * Environment-variable switches are invisible in the command history and in scripts - the color behavior of an invocation becomes unexplainable; a flag is explicit, discoverable and greppable;

* Description:

  * The automatic baseline: color is emitted only when the target stream is a TTY;

  * The only overrides are the flags:

    * `--color` - force the color on, even into a pipe (for TTY-like consumers such as `less -R`);

    * `--no-color` - force the color off;

  * Environment variables (`CLICOLOR_FORCE`, `NO_COLOR`, `CLICOLOR`, `TERM`) do not participate - the flags are the single control interface;

  * ANSI escapes in a redirected stream without `--color` are a violation;

* Benefits:

  * The color behavior of any invocation is readable from the command line itself - nothing hidden in the environment;

  * `cli > file` produces clean data without extra flags;

  * The switch logic is trivial to test: two flags and the TTY state;

* Examples:

  * Case #1 - escapes leaking into a file:

    * Incorrect:

      ```text
      $ mycli list > out.txt
      $ cat -v out.txt

      ^[[96msrc/cli.ts^[[0m
      ```

    * Correct:

      ```text
      $ mycli list > out.txt
      $ cat -v out.txt

      src/cli.ts

      ```

  * Case #2 - forcing color for a TTY-like consumer:

    ```text
    $ mycli list --color | less -R
    ```
