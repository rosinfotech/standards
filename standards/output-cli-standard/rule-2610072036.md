# The Rosinfotech Base Standards

## The Output CLI Standard

### Color

#### Rule #2610072036

* Context:

  * Without a fixed palette every tool invents its own color language: green errors, blue warnings, rainbow headers - the output becomes noise;

* Description:

  * The palette is closed - each color carries exactly one semantic role:

    * headers:

      * level 1 (`== H ==`) - bold + blue;

      * level 2 (`-- H --`) - bold + blue;

      * level 3 (`-- H --`) - blue without bold;

      * level 4 (flat text) - bold + white;

    * messages - colored fully, the prefix bold with the semantic color and the text in the semantic color without bold:

      * `Error:` - red;

      * `Warning:` - yellow;

      * `Success:` - green;

      * `Information:` - cyan;

    * neutral output:

      * cyan - paths and links;

      * gray (bright black) or dim - secondary text: hints (`Hint:`), timestamps, examples;

    * JSON syntax - human mode only:

      * keys - cyan;

      * string values - green;

      * numbers, `true`, `false`, `null` - yellow;

      * punctuation - the default color;

  * Shades: blue is bright blue (94), white is bright white (97) - the basic 34/37 are unreadable on dark terminals;

  * Forbidden: blinking, inverse video, background fills, rainbow runs, color as decoration;

  * Introducing a new role, shade or JSON token requires changing this rule first;

* Benefits:

  * One visual language across all CLIs of the company;

  * Red always means the same thing - the reader stops scanning for meaning;

  * The JSON modes stay readable in every terminal theme;

* Examples:

  * Case #1 - a deploy fragment using the palette (the color noted on the right):

    ```text
    == Deploy report ==            <- bold + blue
    -- Region EU --                <- bold + blue
    - server-a: restarted;         <- default color
    Warning: 2 flaky tests skipped <- bold yellow prefix, yellow text
    Success: deployed in 8.2s      <- bold green prefix, green text
    Hint: see mycli logs           <- gray
    src/cli.ts                     <- cyan (neutral listing)
    ```

  * Case #2 - JSON syntax in human mode:

    ```text
    {
        "name": "src",       <- key cyan, string green
        "count": 12          <- number yellow
    }
    ```

  * Case #3 - color as decoration:

    * Incorrect (magenta banner, inverse highlights):

      ```text
      SOME REALLY IMPORTANT NOTICE        <- magenta + inverse
      ```

    * Correct:

      ```text
      Warning: the maintenance window ends in 10 minutes
      ```
