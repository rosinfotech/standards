# The Rosinfotech Base Standards

## The Output CLI Standard

### Messages

#### Rule #2610072050

* Context:

  * Absolute paths leak machine details and break when pasted into another environment; unquoted paths with spaces split on copy;

* Description:

  * Paths in the output are relative to the repository root with the `/` separator;

  * A path containing spaces is quoted;

  * References to code use the `path/file.ts:26` form - the terminal auto-links it;

  * Paths in neutral output (listings, tables) are cyan per [Rule #2610072036](/standards/output-cli-standard/rule-2610072036.md);

  * Inside a colored message the message color wins - embedded paths are not recolored;

  * Absolute local paths (`/Users/...`, `C:\...`) in the output are a violation;

* Benefits:

  * The output is portable: paths resolve on any checkout;

  * `path:line` references navigate in one click in terminal and IDE;

* Examples:

  * Case #1 - a code reference in a neutral listing:

    ```text
    - src/db/migrations.ts:214;
    ```

  * Case #2 - a path inside a colored message (the whole line is red, the path is not recolored):

    ```text
    Error: cannot read src/features/deployment/…/config.production.yaml
    ```

  * Case #3 - a path with spaces:

    ```text
    Warning: skipped "docs/old drafts/deploy notes.md"
    ```

  * Case #4 - an absolute path:

    * Incorrect:

      ```text
      Error: cannot read /Users/aeza/scopes/rosinfotech/standards/README.md
      ```

    * Correct:

      ```text
      Error: cannot read README.md
      ```
