# The Rosinfotech Base Standards

## The Output CLI Standard

### Typography

#### Rule #2610072042

* Context:

  * Mixed bullets, tabs and ad-hoc indentation break alignment in every terminal but the author's one; without terminators the reader cannot predict whether an item opens details;

* Description:

  * The dash list uses the `- ` bullet - the workhorse for inventories and disclosures;

  * The numbered list uses `1. `, `2. ` items - for step sequences and enumerations of positions;

  * The item casing follows its nature: a phrase opens with a capital letter; an abbreviation at a phrase opening renders fully uppercase (TSV, JSON, ID, URL, API) per [Rule #2601190212](/standards/common-code-style-standard/rule-2601190212.md); a literal inside - a command, a flag, a path, an identifier - keeps its exact spelling;

  * The nesting step is 4 spaces (0, 4, 8); the depth is at most 3 levels;

  * The terminator discipline of [Rule #2609270954](/standards/documentation-standard/rule-2609270954.md) applies to the runtime output:

    * An item with child items ends with `:`;

    * A leaf item ends with `;`;

  * The blank-line discipline inside a nested list:

    * A parent item line is followed by one blank line before its children;

    * A closed children block is followed by one blank line before the next sibling;

    * Leaf siblings run dense - no blank lines between them;

  * Lists render in the text color (per [Rule #2610072036](/standards/output-cli-standard/rule-2610072036.md));

  * Tabs are a violation - spaces only;

* Benefits:

  * The terminators make the structure scannable: `:` promises children, `;` closes the item;

  * The blank-line discipline separates every nesting level without smearing the whole list;

* Examples:

  * Case #1 - a nested dash list:

    ```text
    - Item 1:

        - Item 1.1:

            - Item 1.1.1;
            - Item 1.1.2;

        - Item 1.2:

            - Item 1.2.1;
            - Item 1.2.2;

    - Item 2:

        - Item 2.1;
        - Item 2.2;
    ```

  * Case #2 - a nested numbered list:

    ```text
    1. Item 1:

        1. Item 1.1;
        2. Item 1.2;

    2. Item 2:

        1. Item 2.1;
        2. Item 2.2;
    ```

  * Case #3 - item casing:

    * Incorrect (a phrase starting lowercase):

      ```text
      - fetch the migration list;
      ```

    * Correct (a phrase opens with a capital letter, a literal keeps its spelling):

      ```text
      - Fetch the migration list;
      - git push origin main;
      - src/db/migrations.ts:214;
      ```
