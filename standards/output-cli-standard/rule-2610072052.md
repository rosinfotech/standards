# The Rosinfotech Base Standards

## The Output CLI Standard

### Machine output

#### Rule #2610072052

* Context:

  * A CLI is consumed by other CLIs: scraping decorated human output is fragile; a stable machine mode removes the scraping;

* Description:

  * Machine-readable output is enabled by an explicit flag: `--tsv` or `--json`;

  * TSV is the default machine format - the parallel of [Rule #2609270952](/standards/common-code-style-standard/rule-2609270952.md);

  * JSON modes by stream:

    * a TTY gets pretty-printed JSON with a 4-space indent;

    * a non-TTY stream (pipe, file, CI) gets one compact line;

    * the schema is identical in both forms;

  * Machine mode implies: no color, no progress, no headers or hints on stdout, exactly one trailing newline;

  * The JSON schema is stable: changes are additive (new fields allowed, renames and removals require a major version bump);

* Benefits:

  * `cli list --tsv | column -t` and `cli list --json | jq` work without cleanup;

  * A human reads pretty JSON in the terminal, a machine parses the compact form - one schema, zero surprises;

* Examples:

  * Case #1 - TSV with a header row:

    ```text
    $ mycli list --tsv
    name    status    region
    src     ok        eu
    docs    skipped   eu
    ```

  * Case #2 - JSON in a TTY (pretty, 4-space indent):

    ```text
    $ mycli list --json
    {
        "items": [
            { "name": "src", "status": "ok" },
            { "name": "docs", "status": "skipped" }
        ]
    }
    ```

  * Case #3 - JSON piped (compact):

    ```text
    $ mycli list --json | jq .items[0].name
    "src"
    ```

  * Case #4 - decoration polluting machine mode:

    * Incorrect:

      ```text
      $ mycli list --tsv
      Success: 2 items
      name    status
      src     ok
      ```
