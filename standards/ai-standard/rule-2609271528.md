# The Rosinfotech Base Standards

## The AI Standard

### AGENTS.md

#### Rule #2609271528

* Context:

  * The BASE AGENTS.md makes agent behavior uniform across all company projects; without a fixed composition the file drifts from project to project and agents miss critical prohibitions.

* Description:

  * The BASE AGENTS.md is the behavioral core (the model: [Rule #2609262010](/standards/ai-standard/rule-2609262010.md)): it is identical for every company project and every role, and is copied as-is from the asset [AGENTS-STANDARD-BASE.md](/standards/ai-standard/assets/AGENTS-STANDARD-BASE.md);

  * The core consists of exactly six sections, in this order:

    * AGENTS.md inclusions - the role assets from the standards repository ([Rule #2610031427](/standards/ai-standard/rule-2610031427.md));

    * AGENTS.md self-update - the refresh of the core and the inclusions from the standards repository on the user's request (the model [Rule #2609262010](/standards/ai-standard/rule-2609262010.md));

    * New project - ask for the workspace ([Rule #2610031855](/standards/ai-standard/rule-2610031855.md));

    * Agent scripts - `.agents` and Node.js ([Rule #2610031908](/standards/ai-standard/rule-2610031908.md));

    * Sensitive information ([Rule #2609270958](/standards/security-standard/rule-2609270958.md) with [Rule #2609262020](/standards/ai-standard/rule-2609262020.md));

    * Git - the absolute prohibition ([Rule #2609262015](/standards/ai-standard/rule-2609262015.md));

  * Everything else lives in the role assets, composed in as marked blocks on demand - the functional roles: Harness ([Rule #2610042002](/standards/ai-standard/rule-2610042002.md)), Git Manager ([Rule #2610031647](/standards/ai-standard/rule-2610031647.md)), Technical Writer ([Rule #2610031649](/standards/ai-standard/rule-2610031649.md)), Researcher ([Rule #2610031651](/standards/ai-standard/rule-2610031651.md)) - and the engineering roles (the other rules of this subsection);

  * Placement: the user-global agent config on the engineer's machine and/or the repository root;

  * The Russian trigger phrases in the asset are intentional - the team is Russian-speaking;

  * Per-role and per-project adjustments never land in the BASE AGENTS.md - they belong to the role AGENTS.md files (the other rules of this subsection) and to the repository itself (its Makefile, package.json, build config).

* Benefits:

  * Uniform, predictable agent behavior in every company project;

  * The catalog stays the single source of truth - a rule change propagates by re-copying the asset;

  * Critical prohibitions (git, secrets) can not be accidentally dropped.

* Examples:

  * Case #1:

    * Incorrect:

      * a base AGENTS.md with the git prohibition section edited out to "simplify" CI automation;

    * Correct:

      * the asset copied as-is; the CI workflow adapts to the rules, never the other way around.
