# The Rosinfotech Base Standards

## The AI Standard

### AGENTS.md

#### Rule #2610082250

* Context:

  * The branching model crosses role boundaries - every engineer opens task branches daily; without a dedicated role asset the fork points, gates and sync rhythm drift per project and per team;

* Description:

  * The Git Flow Expert role asset is [AGENTS-STANDARD-GIT-FLOW-EXPERT.md](/standards/ai-standard/assets/AGENTS-STANDARD-GIT-FLOW-EXPERT.md);

  * The asset covers: the ladder of five named variants, the fork-point invariant with the gated-dirt / ungated-dirt classification, the one-way flow and the sync discipline, the hotfix contract, the per-variant contracts with the environment mapping, the versioning layer (tags as the version truth, the stamp protocol, fragments, the stamp message);

  * The asset is isolated and self-contained: it inlines the norms as plain text and carries no rule references - per the assets norm of [Rule #2609271055](/standards/documentation-standard/rule-2609271055.md) the description lives in the rules, not in the asset;

  * The asset's sections mirror the Git Flow Standard - the rules remain the source of truth:

    * the ladder - [Rule #2610082114](/standards/git-flow-standard/rule-2610082114.md);

    * the fork point - [Rule #2610082116](/standards/git-flow-standard/rule-2610082116.md);

    * directions and sync - [Rule #2610082118](/standards/git-flow-standard/rule-2610082118.md);

    * hotfix - [Rule #2610082120](/standards/git-flow-standard/rule-2610082120.md);

    * the variants - [Rule #2610082122](/standards/git-flow-standard/rule-2610082122.md), [Rule #2610082124](/standards/git-flow-standard/rule-2610082124.md), [Rule #2610082126](/standards/git-flow-standard/rule-2610082126.md), [Rule #2610082128](/standards/git-flow-standard/rule-2610082128.md), [Rule #2610082130](/standards/git-flow-standard/rule-2610082130.md);

    * versioning - [Rule #2610092122](/standards/git-flow-standard/rule-2610092122.md), [Rule #2610092124](/standards/git-flow-standard/rule-2610092124.md), [Rule #2610092126](/standards/git-flow-standard/rule-2610092126.md);

  * The role stewards the model, not the operations: staging, committing and pushing stay with the Git Manager asset [AGENTS-STANDARD-GIT-MANAGER.md](/standards/ai-standard/assets/AGENTS-STANDARD-GIT-MANAGER.md) and its explicit-order discipline;

  * Inclusion into AGENTS.md happens per [Rule #2610031427](/standards/ai-standard/rule-2610031427.md);

* Benefits:

  * One role asset for the branching model regardless of the project stack;

  * The Git Flow Standard becomes the single branching-model source for agents;

  * The fork-point, sync and hotfix invariants stop drifting per team - the role guards them mechanically;

* Examples:

  * Case #1 - inclusion into a project AGENTS.md:

    ```markdown
    <!-- AGENTS-INCLUDE: https://raw.githubusercontent.com/rosinfotech/standards/master/standards/ai-standard/assets/AGENTS-STANDARD-GIT-FLOW-EXPERT.md -->

    <!-- /AGENTS-INCLUDE: https://raw.githubusercontent.com/rosinfotech/standards/master/standards/ai-standard/assets/AGENTS-STANDARD-GIT-FLOW-EXPERT.md -->
    ```

  * Case #2 - a task landing in the role:

    * "set up the branch model for the new service - four engineers, a stage environment" - in scope: the variant choice, the gates, the fork points;

    * "commit and push the release" - out of scope: git write operations, the Git Manager territory;
