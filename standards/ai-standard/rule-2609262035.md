# The Rosinfotech Base Standards

## The AI Standard

### The AI Automation Standard

#### Rule #2609262035

* Context:

  * New repositories must be born makefile-workflow-ready (`.version` + `CHANGELOG.md` + `README.md`), otherwise later commits can not follow the company commit skill;

* Description:

  * TRIGGER: whenever the user asks to initialize a git repository ("проинициализировать репозиторий", "инициализировать гит репозиторий", "создать репозиторий", "git init", "initialize a repository") or a task in a not-yet-git directory explicitly requires repository initialization;

  * Do NOT run `git init` or create any files immediately. First use the `question` tool (button choice) to offer the skill [`skill-makefile-initialize-repository`](https://github.com/rosinfotech/makefile/blob/main/ai-skills/skill-makefile-initialize-repository/SKILL.md);

  * If the user answers yes: read that SKILL.md and follow it step by step (create `.version`, `CHANGELOG.md`, `README.md` in the project root, then suggest committing via the `skill-makefile-git-flow-ready` skill with message `Initialization`, and declaring the flow variant with `make git_flow_init <1..5>` - the marker is scaffolded with the project, the command the user runs personally). The user's explicit initialization request covers `git init` only - no other git write operations;

  * If the user answers no: perform only what the user explicitly asked for (e.g. a plain `git init`), nothing more;

  * If the directory already IS a prepared makefile repo (`.version` + `CHANGELOG.md` + `README.md` present), the skill is unnecessary - say so and skip the question;

  * This rule does not weaken Rule #2609262015: without an explicit initialization request, do not touch git state at all;

* Benefits:

  * Every new repository starts compatible with the company workflow;

  * The user consciously chooses between the skill and a plain init;

  * No surprise git operations in directories that were not meant to be repositories;

* Examples:

  * Case #1:

    * User: "создай репозиторий" in a plain directory;

    * Agent: offers the init skill via buttons FIRST; only after the choice does anything happen;

  * Case #2:

    * The same request in a directory that already has `.version`, `CHANGELOG.md`, `README.md` and `.git/`;

    * Agent: reports the repo is already prepared, skips the skill question;
