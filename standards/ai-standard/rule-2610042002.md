# The Rosinfotech Base Standards

## The AI Standard

### AGENTS.md

#### Rule #2610042002

* Context:

  * Agent platforms (harnesses) spawn nested agents - sub-agents, sessions, worktree agents - and a spawned agent without the BASE AGENTS.md loses the behavioral core:

    * the prohibitions;

    * the composition and self-update mechanics;

* Description:

  * When the agent platform (harness) creates another agent, it must create AGENTS.md in the spawned agent's context:

    * the content is the BASE AGENTS.md composed per [Rule #2609271528](/standards/ai-standard/rule-2609271528.md);

    * the source of truth is the asset [AGENTS-STANDARD-BASE.md](/standards/ai-standard/assets/AGENTS-STANDARD-BASE.md);

    * the raw form for the harness: `https://raw.githubusercontent.com/rosinfotech/standards/master/standards/ai-standard/assets/AGENTS-STANDARD-BASE.md`;

  * The spawned agent starts from the clean base - role inclusions are not inherited automatically: the spawned agent composes them on demand (the inclusions section of the base);

  * The harness role asset [AGENTS-STANDARD-HARNESS.md](/standards/ai-standard/assets/AGENTS-STANDARD-HARNESS.md) is the ready-to-copy source of truth for the harness instruction file;

* Benefits:

  * Every spawned agent carries the behavioral core from the first turn - the prohibitions included;

  * The composition mechanics (inclusions, self-update) work uniformly at every nesting level;

  * No agent in the platform runs context-free.

* Examples:

  * Case #1:

    * the harness spawns a worktree agent for a frontend task;

    * the harness creates AGENTS.md in the worktree context - the current BASE fetched from the raw URL - and the spawned agent includes the frontend role asset itself on demand;
