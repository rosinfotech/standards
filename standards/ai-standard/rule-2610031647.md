# The Rosinfotech Base Standards

## The AI Standard

### AGENTS.md

#### Rule #2610031647

* Context:

  * Git operations need a dedicated steward: the commit preparation flow and the repository initialization are multi-step skills that do not belong in the behavioral core of every agent;

* Description:

  * The Git Manager AGENTS.md is a role asset: composed into an AGENTS.md as a marked block on demand (the inclusions: [Rule #2610031427](/standards/ai-standard/rule-2610031427.md)); the ready-to-copy source of truth is the asset [AGENTS-STANDARD-GIT-MANAGER.md](/standards/ai-standard/assets/AGENTS-STANDARD-GIT-MANAGER.md);

  * Role scope: git operations stewardship - the git project setup (the priority part), the commit preparation flow and the repository initialization, all through the makefile skills with the user's explicit confirmation;

  * The priority part - the git project setup (The Git Code Project Standard):

    * the EditorConfig root file ([Rule #2610031936](/standards/git-code-project-standard/rule-2610031936.md)) - copied as-is from the asset into the project root;

    * the makefile vendoring ([Rule #2610031938](/standards/git-code-project-standard/rule-2610031938.md)) - the framework embedded via `make vendor <project-path>` from a clone of the makefile repository;

    * the commit and initialization flows apply once the setup is in place;

  * It implements - inlines the agent-relevant text of, with the full meaning of - the catalog rules:

    * [Rule #2609262030](/standards/ai-standard/rule-2609262030.md) - commit requests: preparation flow only;

    * [Rule #2609262035](/standards/ai-standard/rule-2609262035.md) - repository initialization: ask before init;

  * The base git prohibition ([Rule #2609262015](/standards/ai-standard/rule-2609262015.md)) stays in the BASE AGENTS.md and always wins over this role;

* Benefits:

  * The behavioral core slims down - agents without git duties do not carry the flows;

  * The commit and init flows live in one place, updated from the makefile skills;

  * The prohibition hierarchy stays intact.

* Examples:

  * Case #1:

    * the user asks to prepare a commit in a makefile-prepared repository;

    * the Git Manager runs the question-and-skill flow and ends with the exact `make git_flow_commit_push` proposal - never executing the git writes itself.
