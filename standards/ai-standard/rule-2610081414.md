# The Rosinfotech Base Standards

## The AI Standard

### AGENTS.md

#### Rule #2610081414

* Context:

  * CLI tools cross role boundaries - backend, frontend and infrastructure engineers all occasionally build command-line tools; without a dedicated role asset the output conventions drift per project;

* Description:

  * The CLI Engineer role asset is [AGENTS-STANDARD-ENGINEER-CLI.md](/standards/ai-standard/assets/AGENTS-STANDARD-ENGINEER-CLI.md);

  * The asset covers: command tree and argument parsing, configuration and environment, console output, machine-readable modes, interactive prompts, packaging and distribution;

  * The asset is isolated and self-contained: it inlines the norms as plain text and carries no rule references - per the assets norm of [Rule #2609271055](/standards/documentation-standard/rule-2609271055.md) the description lives in the rules, not in the asset;

  * The asset's Output discipline sections mirror the Output CLI Standard - the rules remain the source of truth:

    * streams and exit codes - [Rule #2610072030](/standards/output-cli-standard/rule-2610072030.md) and [Rule #2610072032](/standards/output-cli-standard/rule-2610072032.md);

    * color gating, the closed palette and color-independent meaning - [Rule #2610072034](/standards/output-cli-standard/rule-2610072034.md), [Rule #2610072036](/standards/output-cli-standard/rule-2610072036.md), [Rule #2610072038](/standards/output-cli-standard/rule-2610072038.md);

    * typography: headers, lists, blank lines, width - [Rule #2610072040](/standards/output-cli-standard/rule-2610072040.md), [Rule #2610072042](/standards/output-cli-standard/rule-2610072042.md), [Rule #2610072044](/standards/output-cli-standard/rule-2610072044.md), [Rule #2610072046](/standards/output-cli-standard/rule-2610072046.md);

    * messages, paths and machine modes - [Rule #2610072048](/standards/output-cli-standard/rule-2610072048.md), [Rule #2610072050](/standards/output-cli-standard/rule-2610072050.md), [Rule #2610072052](/standards/output-cli-standard/rule-2610072052.md);

    * interaction and the approved library list - [Rule #2610072054](/standards/output-cli-standard/rule-2610072054.md), [Rule #2610072056](/standards/output-cli-standard/rule-2610072056.md), [Rule #2610072058](/standards/output-cli-standard/rule-2610072058.md);

  * The asset's Verification section demands the dual-mode check of [Rule #2610072034](/standards/output-cli-standard/rule-2610072034.md) before the work is reported complete;

  * Inclusion into AGENTS.md happens per [Rule #2610031427](/standards/ai-standard/rule-2610031427.md);

* Benefits:

  * One role asset for every CLI regardless of the underlying stack;

  * The Output CLI Standard becomes the single output source for agents;

  * The verification loop (TTY run + piped run) catches stream and color violations mechanically;

* Examples:

  * Case #1 - inclusion into a project AGENTS.md:

    ```markdown
    <!-- AGENTS-INCLUDE: https://raw.githubusercontent.com/rosinfotech/standards/master/standards/ai-standard/assets/AGENTS-STANDARD-ENGINEER-CLI.md -->
    <the full content of the asset>
    <!-- /AGENTS-INCLUDE: https://raw.githubusercontent.com/rosinfotech/standards/master/standards/ai-standard/assets/AGENTS-STANDARD-ENGINEER-CLI.md -->
    ```

  * Case #2 - a task landing in the role:

    * "add a deploy command to the service CLI" - in scope: command, flags, output, exit codes;

    * "fix the deploy API endpoint" - out of scope: the API itself;
