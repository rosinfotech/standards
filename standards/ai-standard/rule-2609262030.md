# The Rosinfotech Base Standards

## The AI Standard

### The AI Automation Standard

#### Rule #2609262030

* Context:

  * The company uses a makefile-based workflow (`.version` + `CHANGELOG.md` + `README.md` in the repository root) with dedicated commit/push skills;

* Description:

  * TRIGGER: whenever the user EXPLICITLY asks to "подготовить коммит", "сделать коммит", "закоммитить" (or "prepare commit", "make commit", "commit") in the current turn;

  * The trigger starts the PREPARATION flow only: the agent prepares everything (the changelog entries proposed from the diffs - fragment lines under variants #2-#5; the CHANGELOG.md section, the `.version` line 2 and `make version_update` only under a declared variant #1 per the skill's non-contradiction conditions; the ADR/runbook assessment and document drafts per [Rule #2610191435](/standards/ai-standard/rule-2610191435.md); the commit message draft) and ends by proposing the exact versioning command (`make git_flow_commit_push "<message>"` for variant #1 and standalone projects, `make git_flow_seal` after a gate merge for variants #2-#5, or a plain `git commit` in the plain flow) for the user to run personally. The agent NEVER executes `git add`, `git commit`, `git push` or `make git_flow_commit_push` itself unless the user explicitly authorized staging in that turn;

  * MANDATORY during preparation: the agent MUST run ALL checks/linters the project defines (`npm run format`, `npm run lint`, `npm run type-check`, tests, etc. - whatever exists in package.json / Makefile) and make them pass (or explicitly report failures and get the user's decision) BEFORE proposing the final commit command;

  * Before doing anything else, check whether the repository is prepared for the makefile workflow: a `.version` file, `CHANGELOG.md` and `README.md` must all exist in the root;

  * If the repo IS prepared: use the `question` tool (button choice) to ask whether to apply the skill [`skill-makefile-git-flow-ready`](https://github.com/rosinfotech/makefile/blob/main/ai-skills/skill-makefile-git-flow-ready/ru/SKILL.md);

  * If the repo is NOT prepared: never silently pick a fallback - report which files are missing and ask whether to bring the repo to the required state (recommended) or proceed with a plain commit;

  * This rule does not weaken Rule #2609262015: an explicit commit request is still required, and pushes still need explicit approval;

* Benefits:

  * Consistent changelog/version discipline across company repositories;

  * No commit is ever proposed with failing checks;

  * The human stays the only executor of git write operations;

* Examples:

  * Case #1:

    * User: "подготовь коммит" in a repo with `.version`, `CHANGELOG.md`, `README.md`;

    * Agent: asks (buttons) whether to apply the makefile skill, runs all checks, prepares the changelog entries and the plan, proposes the versioning command (`make git_flow_commit_push` / `make git_flow_seal`) - and runs no git writes itself;

  * Case #2:

    * Same request, but `CHANGELOG.md` is missing;

    * Agent: reports the missing file, asks (buttons) whether to create the makefile set or make a plain commit; never decides alone;
